# Code audit (#32)

Started 2026-10-16. R2 and physics/model changes are outside this work. The first pass follows data
boundaries and persistence, where a small failure can lose work or prevent an offline session.

| Area | Finding | Status |
|---|---|---|
| Repository manifest | Only its envelope was checked. Malformed entries could reach cache mutations; duplicate paths could produce competing downloads. | Fixed: shared complete shape checks, path validation and duplicate rejection before sync changes. The CLI validator reports malformed manifests instead of throwing. |
| Component cache | A file with a valid hash but invalid content replaced the last valid cached copy before its fields were checked. | Fixed: content validation precedes cache writes. Regression tests preserve the previous copy. |
| Offline reading | JSON `null` crashed the component reader and interrupted the entire cache read. | Fixed: malformed JSON values are rejected independently; valid entries remain available. |
| IndexedDB writes | The wrapper resolves at request success, before transaction completion. A subsequent abort can be reported as a successful save. | Fixed: resolve on transaction completion, reject an abort even after request success. Failed opens can retry; version changes close and discard the old connection. |
| Backup restore | The envelope is accessed without checking JSON `null`; version is not checked, and null entries interrupt restore. | Fixed: validate supported v1/v2 envelopes before writes; reject malformed records independently, count committed records and failed writes, and report unreadable files in the UI. |
| Saved tabs | One malformed entry stopped the loop before later valid tabs; an inaccessible storage read escaped the handler. Invalid metadata could enter the UI. | Fixed: validate each entry independently, preserve active selection by original position, keep missing save snapshots dirty, and show a recovery warning. |
| Display preferences | Stored values were spread over defaults without checking their shape. Unknown languages or null units/groups could stop rendering. | Fixed: validate settings independently, retain valid custom units and choices, and fall back to browser-language/preset defaults. |
| Reaching the storage at all | `window.localStorage` **throws** a `SecurityError` where a browser blocks site data (Safari in a framed page, Chromium with all cookies blocked), and the shell read it in three field initialisers. A user who blocks site data got an **empty page**: headless Chromium with the property made to throw showed `SecurityError: The operation is insecure.` uncaught and `gl-app` holding 0 bytes. | Fixed: `state/browser-storage.ts` asks the browser once through a `try` and answers nothing when refused; the store, the settings and the welcome flag already take a `Storage \| undefined`, `saveSettings` no longer throws out of the click that changed a unit, and the shell says plainly that this browser remembers nothing (`documents.storageDenied`, five languages, German capitalisation corrected by Codex). Verified in the same browser: the app renders whole (183,724 bytes), the warning is shown, the example load opens, nothing is thrown. |
| Record metadata | `getAll()` was cast to the record type, so a value with no usable `id` reached a library, where reading a field off it threw inside the promise the whole list depends on: one bad record emptied the user's library instead of itself. The entries' own metadata was unchecked too — a dateless gun, a component of an unknown `kind` read as a projectile, a load with no name — and the load library's check lived in its IndexedDB wrapper, where no test ever ran it. | Fixed: `keyedRecords()` drops values with no string `id` as they leave a store; each library's `checked()` now also fills a missing date (the epoch) and a missing name (the load's title, else `Untitled`), and drops an entry whose `kind` is none of the three instead of reading it as a projectile. The load library's check moved from `library-storage.ts` into `Library` itself, beside the other two, so it applies whatever the entries were stored in. |
| Typed numbers | `parseNumber` turned the first comma into a decimal point, so `3,445` (as the results themselves print a pressure) or `62,000` psi typed by an English reader became 3.445 and 62: silently wrong by a factor of a thousand, in every numeric input of the app. A French reader's `2,850` means 2.85, so neither reading is safe. | Fixed: a comma before exactly three digits with a non-zero integer part (`isAmbiguousNumber`) is refused everywhere numbers are typed; the editor says why and how to write it (`field.ambiguous`, five languages). `0,325` and `2,85` stay decimal commas. Unit tests in `units.test.ts`. The editor's other input paths were reviewed: drafts are keyed by a field's place in its group, which hidden fields don't shift; positivity is checked before a value reaches the load, and the engine's refusals mark the fields concerned. |

| Untrusted files (third pass, 2026-11-02) | Codex audited every parser of a file a user opens and reproduced eleven faults: a character reference past U+10FFFF and elements nested thousands deep threw out of every XML importer; a thirty-thousand-digit number took a second to reject (quadratic backtracking, the same pattern in the app's `parseNumber`); a GRTrace file of many shots was quadratic in time and, with a long powder name, in memory; a GRTrace text field holding an object threw; a CSV of thousands of columns scanned quadratically and one of 130,000 lines overflowed `Math.max(...)`, as did a gallery of 150,000 pictures spread into `push`; a JSON ladder of 1e308 steps never stopped allocating; a variant tag `__proto__` passed validation with no field checked. | Fixed, each with a test in `packages/formats/test/hostile-files.test.ts` or `chronograph-csv.test.ts`: references checked before conversion, a nesting limit of 200, the number pattern rewritten, shots appended in place and the note built once, text fields read as text only, the CSV bounded at 100 columns and its maxima reduced, pictures pushed one by one, ladders of 2 to 10 whole steps (JSON and GRT; `ladderChargeMasses` caps at 10 too), variant tags looked up as own keys. |
| Engine and review worker (fourth pass, 2026-11-02) | Codex audited what an extreme but parseable load does to the engines and the review, and reproduced six faults: R1 re-filtered every sample for each sample it kept (a load of 137,000 samples ran for minutes); a gun of near-zero mass made R1 and GRT Traditional return infinite recoil as a successful result; charge synthesis, at a rounding index past 2^53 where `step + 1 === step`, retried the same charge forever; R1's temperature review silently ran GRT Traditional, which exhausted memory on a load R1 handled; a worker that threw or died left the latest review pending for ever; with no worker, a superseded review was still delivered. | Fixed with tests (`research.test.ts`, `review-client.test.ts`): the last sample at rest found once; `simulation-check.ts` refuses any non-finite figure or curve as `numerical-failure` in both engines; synthesis gives up on rounding indices that are not safe integers; the temperature range runs the selected engine; the worker answers `failed` on an exception, the client fails waiting requests on `error`/`messageerror` and starts a new worker, and the app says the review failed; the fallback computes later and only for the latest request. |
| Searches, assistants, data and CLI (fifth pass, 2026-11-02) | Codex audited the engine's searches, the app's assistants and views, and the data and CLI packages, and reproduced fourteen faults (data and CLI: none; a CLI command named `toString` and an unreadable file, and long shot strings and curves spread into `Math.max`, were found beside it). The cartridge designer said "Saved" when the storage refused the save; an older photo decode replaced a newer one, and a photo or component file that failed escaped unreported; the temperature fit could return a coefficient that can't be simulated, and both calibration searches reported a NaN target reached; axis ticks looped for ever near 1e20 or the largest double; a shot group of 100,000 hits hung the display; OBT node times and extreme but parseable inputs (a temperature of 1e308 K, a maximum pressure of 1e-320 Pa, velocities of 1e308 m/s, k below 1) produced ∞ or NaN shown as figures. | Fixed with tests: the designer saves through a function and reports a refusal; photo choices are numbered and failures shown; imports report per file, one transaction each; the fit's coefficient is simulated once more and dropped unless it matches to 0.1 m/s; non-finite or nonpositive targets are refused; ticks are counted, not summed, and capped at 1,000; a group holds at most 1,000 hits (format, dialog); OBT refuses non-finite lengths; every displayed figure that is no number shows as `—` (`formatNumber`, `formatQuantity`), powders without factors sort last, and the speed of sound no longer overflows. Checked in Chromium for the designer, photo and import messages. |
| Shell and state (sixth pass, 2026-11-03) | Codex audited the shell, the larger views and dialogs, and `state/`, and reproduced twelve defects: two tabs of the app shared one recovery record, so a second tab that closed the loads it inherited wiped the first's unsaved work, and a stale tab's save overwrote what another had saved; keyboard Save and Close ran before a focused note committed; compare, ladders and measurements simulated with GRT Traditional whatever engine was chosen; a component file read slowly went into the tab activated meanwhile; a refused gun save closed the dialog and lost the draft, a refused gun import cleared its own error, invalid gun numbers left the old values to be saved; the chronograph dialog stored its prefilled charge at the display's decimals; a backup could be taken before the library was read; a failed file read or library write stopped or silently shortened an import; a refused removal was an unhandled rejection. | Fixed with tests: one tab keeps recovery by a Web Lock (`recovery-lock.ts`) and the next adopts its loads; library saves are conditional writes in one transaction (`putIf`, `LibraryConflict`); commands blur any focused text field first; every view and search takes the selected engine; file opening carries the destination tab's id into its dialogs; the gun dialog saves through a function, flags bad numbers and stays open on failure; an untouched prefilled charge keeps its exact mass, and editable numbers are prefilled without thousands commas (`formatEditable`); the backup waits for the stores; imports report per file; removals report failure. Checked in Chromium, the recovery lock with two real tabs. |

Validation: 878 tests, typecheck and production build pass. Native Chromium reproduced an IndexedDB
request succeeding and then aborting; the save previously resolved with no stored record and now
rejects with `AbortError`. Browser checks also cover unreadable files and partial backup recovery. The published data
repository's 463 files also validate. This is an ongoing audit, not a claim that every module has been
reviewed. Document workflow findings and remaining history work are in [ui-audit.md](ui-audit.md).

Denied browser storage and record metadata are both done. The second pass, the editor's own input
handling (2026-11-02), found the ambiguous thousands comma (row "Typed numbers"). The document workflow
findings of [ui-audit.md](ui-audit.md) are done too (#34, Undo/Redo and Reopen closed).

The IndexedDB distinction follows the [transaction lifecycle](https://w3c.github.io/IndexedDB/#transaction-lifecycle):
a successful request precedes the transaction commit.
